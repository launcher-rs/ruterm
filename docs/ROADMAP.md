# RuTerm 路线图

> 功能只收**远程连接相关**且我们目前没有的，按「价值 / 成本」排序；
> 界面与交互上的可借鉴点单列一节（见「界面与交互」）。
> 已具备的能力不重复列，明确不做的见「非目标」。
>
> 定位：**远程连接工具，终端为核心**。SSH / Telnet 是远程连接，VNC / RDP / SPICE 也是，
> 所以远程桌面保留在 P2（不承诺排期）；而 AI 助手、内置浏览器、URL 用浏览器打开属于终端之外
> 的另一类产品能力，不做。

## 界面与交互（可借鉴清单）

> 先说结论：原型的**视觉皮**不值得抄——egui 默认控件、emoji 当图标、深色硬编码（`#141821`），
> 切换主题时终端内外不同步。我们的框架主题、`IconName` 图标集、纯图标轨更整齐。
> 真正值得借的是**信息怎么摆、反馈放在哪**：下面这张表。

**查找条的取值边界**：rgpui-term 只给 `SearchStatus { Idle, Invalid, NotFound, Matched }`
与 `search_current()`，没有总匹配数。所以别照抄原型的「3/17」计数，改成状态文案
（「未找到」「正则非法」；命中就静默高亮 + 上下跳转）。原型只支持子串，我们反而能多给
一个「正则」开关：`search()` 走正则，`search_literal()` 走字面量。
顺带一提，rgpui-term 首次搜索从光标位置向后找并自动回绕，和原型「先落在最新输出附近」的手感一致，不用额外做。

**沿用的设计约定**（写进后续所有界面改动）：

1. 颜色只取主题语义色，终端配色走 `ThemeManager` 预设，不学原型硬编码；
2. 图标只从 `IconName` 里选，不混 emoji（原型 🖥/🌐/📁/🔍 字号与基线都不齐）；
3. 低频操作悬停揭示、高频操作常显，但键盘等价路径必须有（关标签要有快捷键）；
4. 反馈尽量落在操作点：能就地提示就别只改状态栏，状态栏是兜底不是主渠道；
5. 非显然控件写「后果型」tooltip，而不是复述名字——原型的跳板机说明、
   「密码（可空，连接后提示）」都是好例子；
6. 不可用就禁用 + 说明原因（tooltip），不要隐藏，也不要点了没反应；
7. 不照抄装饰：原型「跟随系统」主题没有处理逻辑，`🎬 开始录制` 是死按钮。

**不借鉴**（我们已经更好，或与产品调性不合）：

- 密集工具栏（12 个「图标 + 文字」竖排按钮）——我们刚改成纯图标轨 + 悬停提示，别回退；
- 常驻快捷连接条（地址 / 跳板机 / 认证 / 凭据 / 连接 挤成一行）——吃终端高度，
  会话菜单 + 主机表单已覆盖；
- 设置窗口的折叠分组 +「保存并应用」——我们左导航分页、即时生效更好；
- 状态栏塞快捷键提示（`Ctrl+N 新建 | …`）——菜单项自带快捷键徽标；
- emoji 图标、硬编码深色、把 AI 状态常驻状态栏。

- [x] **远程桌面与主机的文件互传** — `M` — 已完成（实机待复核）
  - **RDP 剪贴板文件**：本地复制文件（资源管理器里 Ctrl+C）后，在远端桌面 Ctrl+V 即可粘贴；
    远端复制的文件也能在本机资源管理器粘贴。走 CLIPRDR 文件流（`FileGroupDescriptorW` +
    `FileContentsRequest/Response`），不是 RDPDR 共享盘。实现见 `vendor/cliprdr-native`：
    上游 0.9 的 Windows 后端移植回 cliprdr 0.7，`WinClipboard::new` 默认开启文件传输。
  - **剪贴板窗口独立线程**：剪贴板监听窗口、窗口子类与 OLE 都归 `WinClipboard` 自己起的线程，
    消息循环用阻塞式 `GetMessageW`；`src/desktop/rdp.rs` 不再给会话线程开 OLE STA、也不再每 10ms
    泵消息。原因是 `WM_RENDERFORMAT` 必须同步等远端答复，而答复由 RDP 会话循环驱动——同线程会
    互相等到 10s 超时，表现为本机粘贴远端内容时整窗卡住；分开后等待只阻塞剪贴板线程。
  - **修饰键转发**：rgpui（与 gpui 一致）对 Ctrl / Shift / Alt / Win / CapsLock 只发
    `ModifiersChangedEvent`、不发 KeyDown / KeyUp，所以桌面标签按状态差异补发按下 / 抬起，
    并在点击画面捕获键盘时以 `window.modifiers()` / `window.capslock()` 做基线；
    `Esc` 释放捕获时先把仍按着的修饰键抬起。捕获期间由 `App::intercept_keystrokes` 阻止动作分发，
    `Ctrl+W` / `Ctrl+B` 等应用快捷键不会抢走远端的组合键（capture 监听仍照常转发）。
  - **剪贴板上报不再看窗口是否前台**：上游 0.9 的后端只在监听窗口不处于前台时把本地剪贴板报给远端，
    而拖放恰恰发生在 ruterm 处于前台时，更新会被整个挡掉。`vendor/cliprdr-native` 去掉了这条过滤，
    回环仍由 `owns_clipboard()`（窗口所有者 + OLE 当前对象）兜底。
  - **保存主机时记住表单密码**：保存 / 修改表单里的密码按主机 id 加密写入凭据库（与 SSH 密码同一套），
    同时按 `user@host:port` 写进进程内 `password_cache`；点已保存主机直接复用。认证失败会同时清掉
    内存键与库里的旧密码并清空标签里的密码，下次点行重新询问，改过密码后不会继续拿旧密码重试。
  - **桌面标签拖放**：把文件 / 文件夹拖到 RDP 标签，会话线程把它们写成 `CF_HDROP` 放进本机剪贴板，
    CLIPRDR 监听随即把文件列表报给远端，收到远端 `FormatListResponse` 后再补一次 Ctrl+V
    （慢远端 2s 兜底），资源管理器就落到当前文件夹；不需要远端装 SSH 或额外软件。
    远端未响应时可手动按 Ctrl+V。
  - **上传进度**：本地副本新增 `upload` 模块做进程级登记——拖放时按源路径登记总量与文件数
    （`begin_upload`），剪贴板线程受理并回执后 `attach` 认领、每应答一段 `FileContentsRequest`
    累加已发字节；会话线程按 200ms 轮询，`Event::Upload` 送界面，画面右下角浮出
    「正在粘贴 N 个文件到远端」进度卡片（`已发送 / 总大小`）。结束 / 中断自动移除，
    中断时状态栏给出已传字节。文件报给远端后一直没有回执与读取、或接收开始后
    20s 没有新字节则判定超时并取消（大目录枚举另有 60s 宽限；远端已回执但还没读
    字节时给 120s，等覆盖确认框），不会挂一条不动的进度条。
  - **同名文件**：粘贴走的是远端资源管理器，目标目录已有同名文件时会弹「替换或跳过」，
    这一步只能在远端点；没点之前一个字节都不会传，界面按「远端还没开始接收」提示。
    旧版本留下的半截文件要先在远端删掉或选「替换」，否则每次都会停在这个确认框上。
  - **13MB 只到 4KB 的截断加固**：远端回执后文件列表不再随下一条剪贴板内容失效——
